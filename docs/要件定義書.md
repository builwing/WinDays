## 0. 決定事項（前提）

| 論点 | 決定 |
| --- | --- |
| アプリ名 | **WinDays**（WinLife は同名サービスが多く不採用。WinTask「やるべきこと」に対する「過ごした日々」の対） |
| 目的 | 無料アプリで検索流入を得て、**同一アカウントのまま** WinTask（グループ共有・法人機能）へ誘導する |
| アカウント | **WinTask と共通**。WinDays での新規登録＝WinTask の `users` に Free プランで作成 |
| バックエンド | **WinTask の Laravel に相乗り**（別システムにしない）。バックエンド変更は WinTask リポジトリ側で worktree を使って行う |
| プラットフォーム | **Web（PWA）ファースト**。検索流入が主戦場のため。ネイティブは将来 |
| ドメイン | フロント `days.winroad.org`。API は **`api.days.winroad.org` のエイリアスを切る**（同じ Laravel を指す Nginx vhost を追加。CORS は両ホストを許可） |
| 無料制限の置き方 | **記録（入力）は無制限**。制限は「長期の振り返り・高度レポート」側に置く（入力を制限すると集客アプリとして機能しない） |
| 入れないもの | バックグラウンド GPS 追跡／SNS 的な公開・共有機能（[§13](#13-あえて入れないもの)） |
| 予定の実体 | **`days_plans` を新設**（WinTask `calendar_events` は流用しない） |
| Free の遡り上限 | ダッシュボード直近 4 週。**WinTask の `diary_history_days` を Free 7 日 → 28 日に引き上げ**て整合させる |
| 習慣と定期タスク | **習慣（Free 5 件）は無料、WinTask の定期タスク化は有料**（`recurring_enabled`）という線引き |
| メール認証 | WinDays 経由の新規登録は必須。**WinTask 既存ユーザーには適用せず `email_verified_at` を一括で埋める** |
| アナリティクス | **GA4（無料）**。Cookie 同意バナーを実装し、同意後にのみ読み込む |
| アカウント削除 | **本人操作の `DELETE /me` を WinTask に追加**し両アプリ共通。ガードは `user:purge` の規則を流用 |
| 写真ストレージ | **VPS ローカル**（`storage/app/days/`）で開始。容量逼迫時に S3 互換へ移行できるよう `Storage` ディスク経由で実装 |
| メール配信 | 本番の WinTask は現在 `MAIL_MAILER=log`・`QUEUE_CONNECTION=sync`（実送信していない）。**Phase 0 で Xserver の SMTP（送信元 `no-reply@winroad.jp`）を使った実送信基盤を整える**。`winroad.org` の DNS/MX は触らない。SES は送信量が増えたときの移行先（[§7.4](#74-メール配信基盤)） |
| GitHub | `builwing/WinDays`（private）作成済み |
| 名称の最終確認 | ストア検索は実施済み（[§15.1](#151-決定済み)）。J-PlatPat（9 類・42 類）は着手前にユーザーが実施 |
| 命名の注意 | WinTask 内蔵機能が既に「行動記録（日記）」を名乗るため、WinDays のコア記録は **「タイムログ」** と呼ぶ |

## 1. 目的・背景

WinTask は「メイン担当を競って獲得する」グループ向けタスク管理アプリで、個人 Free／個人有料／法人プランと Stripe 課金基盤まで整っている。一方、集客導線が弱く、有料・法人機能へ到達するユーザーの母数が足りない。

WinDays は、それ単体で検索されて使われる価値を持つ**無料の個人向け行動管理アプリ**として提供し、以下を狙う。

1. 「時間の使い方 可視化」「ワークライフバランス アプリ」「習慣 記録 無料」などの検索キーワードからの流入
2. 登録＝WinTask アカウントとすることで、誘導を「別アプリの案内」ではなく「同じアカウントで使える機能の解放」にする
3. WinDays で蓄積したタイムログ・習慣・日次サマリを、WinTask の個人タスク・日記・共有日報へそのまま接続し、**データの連続性**を乗り換え動機にする

既存資産の再利用（WinTask 側）:

| 既存資産 | WinDays での使い方 |
| --- | --- |
| Sanctum 認証・`POST /register` `POST /login` | 共通アカウント。そのまま利用 |
| `PlanService` / `config/plans.php`（個人 Free/Plus/Pro） | WinDays の無料制限（履歴日数・習慣数など）を同じカタログに追加 |
| 定期タスクの RRULE エンジン（毎週曜日・第n曜・土日祝スキップ・前後営業日シフト） | 習慣（定期行動）の発生日計算に流用 |
| `tasks:send-reminders`（15分ごと）とスケジューラ | 習慣・予定リマインダー、週次振り返りメールの送信基盤 |
| `diary_entries`（1日1件・タグ・気分・Free は直近7日） | WinDays の「1日サマリ」の保存先。**WinDays 側で新テーブルを作らず、WinTask 日記をそのまま使う** |
| `POST /me/tasks`（個人タスク） | 「明日もやる」→ 個人タスク化の導線 |
| `calendar_events`（予定・リマインダー） | 予定（プラン）の候補基盤（[§15](#15-確認事項実装前に決めたいこと) で流用可否を決める） |
| `landing/`（利用規約・プライバシー・特商法） | 法的ページの共通化 |

## 2. 用語定義

| 用語 | 定義 |
| --- | --- |
| ユーザー | WinTask と共通のアカウント（`users`）。WinDays から登録すると Free プラン |
| タイムログ（セグメント） | 「何時から何時まで、何をしていたか」の帯。1日は複数のセグメントで構成される。WinDays のコア記録 |
| カテゴリ | セグメントの分類（仕事・家事・レジャー・移動・睡眠・学習など）。色を持ち、ユーザーがカスタムできる |
| 領域（ドメイン） | カテゴリの上位区分。`work`（仕事）／`life`（プライベート・レジャー）／`rest`（睡眠・休息）の3種固定。バランス集計の軸 |
| 予定（プラン） | その日「こう過ごす」と事前に引いた帯。実績（タイムログ）と重ねて予実対比する |
| 習慣（定期行動） | 「毎朝ラン」「第2土曜は釣り」など繰り返し行う行動の定義。RRULE で表現し、達成／未達成を記録する |
| ストリーク | 習慣の連続達成回数 |
| 1日サマリ | その日のタイムログから自動生成する要約＋ひとことメモ。実体は WinTask の `diary_entries`（`team_id = null`） |
| チェックイン | レジャー用途の「どこで何をしたか」を写真1枚＋場所名で残す手動記録（GPS 常時追跡ではない） |
| ルーティン（テンプレート） | 「平日の基本パターン」など、予定の帯をまとめてワンタップで展開する雛形 |
| 導線 | WinDays から WinTask の機能へ移る UI（同一アカウントで、ログインし直しなしに遷移する） |

## 3. 想定ユーザー / 利用シーン

- **仕事の時間管理をしたい個人**（フリーランス・裁量労働・リモートワーカー）: 1日の作業時間の内訳を把握し、予定どおり進んだかを振り返る
- **趣味・レジャーの記録を残したい人**: 週末の釣り・登山・旅行を写真1枚と場所で残し、「今年何回行けたか」を見返す
- **仕事と生活のバランスを見直したい人**: 週次・月次の「仕事:プライベート比率」の推移を見て働き方を調整する
- **習慣化したい人**: ランニング・学習・早起きなどのストリークと達成率を追う
- 上記が「チームでも共有したい」「タスクとして管理したい」と思った瞬間が、WinTask への誘導ポイント

## 4. 機能要件

### 4.1 認証・アカウント（WinTask 共通）
- [ ] メールアドレス + パスワードで新規登録（＝WinTask `users` に Free で作成）
- [ ] ログイン / ログアウト（Sanctum トークン。WinTask `POST /api/v1/login` を利用）
- [ ] **メール認証を必須化**（捨てアカウント・スパム対策）。WinTask では現在 `MustVerifyEmail` 未有効のため WinTask 側で有効化する。**既存ユーザーは移行時に `email_verified_at` を一括で埋め、再認証を求めない**
- [ ] パスワードリセット（メール）
- [ ] 登録時の同意: 利用規約・プライバシーポリシー（必須）／「WinTask などの関連サービスのお知らせを受け取る」（任意チェック・オプトイン）
- [ ] プロフィール（表示名・タイムゾーン。既定 `Asia/Tokyo`）
- [ ] 既に WinTask を使っているユーザーは同じ資格情報でそのままログインできる
- （提案）Google ログイン（Phase 4）

### 4.2 カテゴリ管理
- [ ] 初期カテゴリを自動投入（仕事／会議／家事／食事／移動／レジャー／学習／運動／睡眠／その他）。各カテゴリは領域（work/life/rest）と色を持つ
- [ ] カテゴリの追加・名称/色/領域の変更・並び替え・アーカイブ（過去ログは残す）
- [ ] タグ（自由入力・複数）でカテゴリを横断した分類

### 4.3 タイムログ（コア機能）
- [ ] **ワンタップ計測**: 「今から〔仕事〕」で開始、「終了」で区間を確定。進行中セグメントは1つのみ。切替は前のセグメントを自動終了
- [ ] **あとから帯入力**: 1日のタイムライン（縦帯）上でドラッグして区間を作成・伸縮・移動。分単位（既定 5 分刻み、設定で 1/5/15 分）
- [ ] セグメントの編集: カテゴリ・開始/終了・タグ・メモ（短文）
- [ ] 日をまたぐセグメント（睡眠など）の扱い: 記録は1本、集計は日付境界で分割
- [ ] 重複区間の禁止（同一時刻に2つのセグメントは置けない。予定とは重なってよい）
- [ ] 未記録（空白）時間の表示。「空白を〔睡眠〕で埋める」などのクイック操作
- [ ] 日付ナビゲーション（前日/翌日/カレンダー）。今日に戻る
- [ ] 直近使ったカテゴリのクイックボタン
- [ ] オフライン時の入力をローカルに保持し、復帰後に同期（PWA）

### 4.4 予定（プラン）と予実対比
- [ ] 予定の帯を引く（カテゴリ・開始/終了・タイトル任意）
- [ ] タイムライン上で予定（左列）と実績（右列）を並べて表示
- [ ] 「予定どおり率」= 予定と実績が同カテゴリで重なった時間 ÷ 予定合計時間
- [ ] 予定を実績にコピー（「予定どおりだった」ワンタップ）
- [ ] 予定は繰り返し（習慣）から自動生成されるものと手動のものがある
- 予定の実体は **`days_plans`（新設）**。WinTask の `calendar_events` とは独立させる（将来の連携は Phase 4 の検討事項）

### 4.5 習慣（定期行動）
- [ ] 習慣の定義: 名称・カテゴリ・繰り返し（RRULE。毎日／毎週(曜日)／毎月(日・第n曜)／毎年）・目安時間帯・目標時間（任意）
- [ ] **WinTask の RRULE エンジンと土日祝スキップ・営業日シフトを流用**（WinTask の `recurring_enabled` ゲートとは独立した WinDays 用の上限を設ける）
- [ ] 当日の習慣一覧と達成チェック（タイムログに該当カテゴリのセグメントがあれば自動達成、手動チェックも可）
- [ ] ストリーク（連続達成）と達成率（週/月）
- [ ] 一時停止・再開・終了日
- [ ] 発生日のライブプレビュー（WinTask `POST /recurring-tasks/preview` と同じ考え方）

### 4.6 リマインダー・通知
- [ ] 習慣・予定の開始 N 分前リマインダー（メール。WinTask の `tasks:send-reminders` 基盤を流用）
- [ ] 「今日まだ記録がありません」の夜間リマインダー（時刻設定・ON/OFF。WinTask の `diary_reminder_time` と同じ作法）
- [ ] 週次振り返りメール（後述 4.8）
- [ ] Web Push（PWA）はメール確立後に Phase 3 で追加
- [ ] 無料ユーザーのメール送信数に上限（例: 1日 10 通）を設け、超過分は翌日に繰り越さず破棄

### 4.7 ダッシュボード（このアプリの顔）
- [ ] **日**: 領域別（work/life/rest）の円グラフ、カテゴリ別内訳、記録カバー率（24h のうち記録済み時間）
- [ ] **週・月**: 領域比率の推移（積み上げ棒）、カテゴリ別合計時間ランキング、予定どおり率の推移、習慣達成率
- [ ] **バランス指標**: 「仕事:プライベート比率」を1つの数字で示し、前週比を表示
- [ ] 期間比較（今週 vs 先週、今月 vs 先月）
- [ ] 無料制限: 集計期間の遡り上限（例: Free は直近 4 週まで。全期間は Personal Plus 以上）

### 4.8 1日サマリ・週次振り返り
- [ ] その日のタイムログから「今日の記録」を自動下書き（例: 仕事 6.5h（会議 1.5h）／運動 0.5h／レジャー 2h）＋ひとことメモ＋気分（1〜5）
- [ ] **保存先は WinTask の `diary_entries`（`team_id = null`、1日1件）**。WinDays 専用の日記テーブルは作らない。WinTask の日記画面からも同じ内容が見える
- [ ] 週次振り返りメール: 「今週は仕事 62%・プライベート 18%・休息 20%。予定どおり率 71%、習慣達成 5/7」。毎週日曜夜（時刻設定可）。再訪の主トリガー。配信は本人の設定で ON/OFF
- [ ] 履歴閲覧は WinTask の `diary_history_days` に従う。**Free を 7 日 → 28 日に引き上げ**、ダッシュボードの遡り 4 週と一致させる（WinTask 側 `PlanService::personalCatalog()` の変更）

### 4.9 チェックイン（レジャー用途・Phase 3）
- [ ] 場所名（手入力）＋写真 1 枚＋メモをセグメントに添付
- [ ] 写真は端末で縮小してからアップロード（長辺 1600px・容量上限はプランの `attachment_max_mb` を流用）
- [ ] 位置情報は「チェックインした瞬間の1点」のみ、かつユーザーが明示的に「現在地を付ける」を押したときだけ取得。バックグラウンド取得はしない
- [ ] 月別の「行った場所」一覧（写真グリッド）

### 4.10 ルーティン（テンプレート・Phase 3）
- [ ] 「平日」「休日」などの予定パターンを保存し、任意の日にワンタップ展開
- [ ] 展開後は個別に編集可能（テンプレートとの紐付けは持たない）

### 4.11 エクスポート
- [ ] タイムログ・習慣ログの CSV エクスポート（期間指定）。**無料でも全期間可**（データを人質に取らない方針）
- [ ] 1日サマリは WinTask 既存の `GET /me/diary/export` を利用

### 4.12 WinTask への導線（設計の肝）
- [ ] **「明日もやる」ボタン**: セグメントから WinTask の個人タスクを作成（`POST /me/tasks`）。作成後「WinTask で見る」リンク
- [ ] **「タスクにする」**: 習慣を WinTask の定期タスクへ変換する案内。**習慣は無料（Free 5 件）、定期タスク化は有料**（Free は `recurring_enabled = false`）という線引きで、ここが有料プランの自然な訴求点
- [ ] **「チームで共有」**: 1日サマリを共有日報にする操作。WinTask の日記共有（`team_id` 付与）へ誘導。Free でも Team×1・招待1名まで可能なので「まず2人で試す」導線になる
- [ ] **シームレスなログイン引き継ぎ**: `days.winroad.org` から `task.winroad.org` へ遷移する際にログインし直しを求めない。サブドメイン間でトークンは共有されないため、ワンタイムコード方式の引き継ぎ API を WinTask 側に追加する（`POST /auth/handoff` → コード発行 → 遷移先で `POST /auth/handoff/exchange`。有効 60 秒・1回限り）
- [ ] 導線の表示タイミングは「共有したくなった瞬間」「繰り返したくなった瞬間」に限定し、常時バナーは出さない
- [ ] 導線クリック・遷移・WinTask 側での Team 作成までを計測（[§4.13](#413-計測アナリティクス)）

### 4.13 計測（アナリティクス）
- [ ] ファネル: 訪問 → 登録 → 初回記録 → 7日継続 → 導線クリック → WinTask で Team 作成
- [ ] イベント記録は WinTask API 側の軽量テーブル（`funnel_events`）に POST。個人特定情報は含めず `user_id` と匿名イベント名のみ
- [ ] ページ解析は **GA4（無料）**。Cookie 同意バナーを表示し、同意後にのみ gtag を読み込む（未同意時は GA4 を一切ロードしない）。同意状態は `localStorage` に保持し、設定画面から撤回可能
- [ ] 運営者向け集計は WinTask の `/admin`（SuperAdmin）に WinDays 用 KPI を追加

### 4.14 法務・信頼
- [ ] 利用規約・プライバシーポリシーは WinTask `landing/` の法的ページを共通化（運営: 株式会社ウィンロード）。利用目的に「関連サービス（WinTask 等）の案内」を明記
- [ ] お知らせメールは**オプトイン**（特定電子メール法）。全メールに配信停止リンク
- [ ] 特商法表記は無料のみでは不要。有料プランへの導線は WinTask 側の表記ページへリンク
- [ ] 行動記録は機微情報になり得るため**既定は完全非公開**。共有は WinTask 側の役割に限定
- [ ] アカウント削除（本人操作）。**WinTask に `DELETE /me` を追加し両アプリ共通**にする。`user:purge` と同じガード（Team/法人のオーナー・有効な Stripe サブスクがある場合は削除を拒否し、先に譲渡/解約を案内）。パスワード再入力必須

## 5. 非機能要件

| 区分 | 要件 |
| --- | --- |
| 性能 | 通常操作の API 応答 1 秒以内。日次タイムライン描画は 100 セグメントで体感遅延なし |

## 7. 技術構成

### 7.1 フロントエンド（`/var/www/WinDays`・本リポジトリ）
- React + Vite + TypeScript + Tailwind CSS（WinTask `web/` と同じバージョン系に揃え、型定義・API クライアントの流儀を共有）
- 状態: TanStack Query（サーバ状態）＋ Zustand（UI 状態・進行中セグメント）
- ルーティング: react-router。フォーム: react-hook-form + zod
- タイムライン描画: DOM（div 帯）＋ Pointer Events。Canvas は不要
- グラフ: Recharts（円・積み上げ棒・折れ線）
- PWA: `vite-plugin-pwa`（Service Worker・マニフェスト・オフラインキュー）。オフライン入力は IndexedDB（idb）に保持
- 日付: date-fns（`Asia/Tokyo` 固定から開始し、タイムゾーンはユーザー設定で拡張）
- 配信: 静的ビルドを Nginx で `days.winroad.org` から配信。LP・解説ページは同じビルドに含める（SSR は不要。SEO 対象ページはプリレンダー）

### 7.2 バックエンド（WinTask リポジトリ `backend/`・Laravel）
- 既存の Sanctum 認証・`PlanService`・スケジューラ・メール送信をそのまま利用
- 追加: WinDays 用マイグレーション（[§8](#8-データモデル)）、`Api/Days/*Controller`、Policy、`days:*` artisan コマンド（週次振り返りメール、休眠整理）
- API ホスト: `api.days.winroad.org` の Nginx vhost（`deploy/nginx/api.days.winroad.org.conf`）を追加し、既存 `api.task.winroad.org` と同じ Laravel を指す。Let's Encrypt 証明書を発行
- CORS: `config/cors.php` の `allowed_origins` に `https://days.winroad.org` を追加
- WinDays のフロントは `VITE_API_BASE_URL=https://api.days.winroad.org/api/v1` を使う
- 変更: メール認証必須化（既存ユーザーは一括 verified）、`throttle` 追加、ログイン引き継ぎ API、`DELETE /me`、`personalCatalog()` への項目追加と `diary_history_days` Free=28
- **作業は WinTask 側の安全規則どおり worktree（`/var/www/WinTask-rf` 方式）で行い、デプロイスクリプト `deploy/windays-phaseN-deploy.sh` を用意する**

### 7.4 メール配信基盤

本番の WinTask は現在 `MAIL_MAILER=log`・`QUEUE_CONNECTION=sync` で、メールを実送信していない。WinDays はメール認証・リマインダー・週次振り返りがコア機能のため、**Phase 0 で実送信基盤を整える**。

| 項目 | 決定 |
| --- | --- |
| 送信サービス | **Xserver の SMTP**（既契約のメール機能を利用。追加コスト・新規アカウントなし）。開発・検証は引き続き `log` |
| Xserver の送信目安 | 全プラン共通で **1 時間 1,500 通・1 日 15,000 通**。著しく超えると利用制限がかかるため、キューで送信レートを絞る（下記） |
| 送信ドメイン | **`winroad.jp`**（Xserver `sv14762.xserver.jp` でメール運用中。SPF に `include:spf.sender.xserver.jp`、DKIM `default._domainkey` 設定済み）。`no-reply@winroad.jp` を作成し From にする。Reply-To はサポート用アドレス。**`winroad.org` は VPS の Postfix がメールを受けており（MX → VPS、SPF は VPS のみ許可）、DNS・MX は一切変更しない** |
| 送信ドメイン認証 | `winroad.jp` は SPF・DKIM 設定済み。**DMARC が未設定**のため、Xserver サーバーパネルの「DMARC設定」で `p=none`（レポート受信）から追加し、運用が安定したら `p=quarantine` へ。DNS は `ns1〜5.xserver.jp` 管理のためパネルから直接反映される |
| Laravel 設定 | `MAIL_MAILER=smtp`、`MAIL_HOST=sv14762.xserver.jp`、`MAIL_PORT=465`・`MAIL_ENCRYPTION=ssl`（または `587`・`tls`）、`MAIL_USERNAME=no-reply@winroad.jp`、`MAIL_FROM_ADDRESS=no-reply@winroad.jp`、`MAIL_FROM_NAME="WinDays"` |
| 送信量の見込み | 無料ユーザー 1,000 人の場合: 週次振り返り 1,000 通/週 ＋ リマインダー（上限 10 通/日・実利用率 20%・平均 2 通と仮定）約 400 通/日 ＝ **月 1.6 万通前後、1 日 500 通前後**。週次振り返りの集中日も目安内 |
| キューとレート制限 | `QUEUE_CONNECTION=database` に切替え、`php artisan queue:work` を systemd で常駐（WinTask の既存メールもキュー経由になり、API 応答が改善する）。メール送信ジョブに **1 分あたり 20 通**のレート制限ミドルウェアを付け、週次振り返り 1,000 通は約 1 時間かけて送る。`days:weekly-digest` はユーザー単位でジョブを投入する |
| バウンス・苦情 | Xserver には Webhook 通知がないため、**`no-reply@winroad.jp` 宛のバウンスメールを Xserver の IMAP（`sv14762.xserver.jp:993`）から定期取り込み**（`days:ingest-bounces`・1 時間ごと）し、ハードバウンス／苦情のアドレスは `users.mail_suppressed_at` を立てて送信停止。送信失敗は `failed_jobs` で拾って再送 |
| 配信停止 | 全メールに署名付き URL の配信停止リンク（`List-Unsubscribe` ヘッダも付与） |
| SES への移行 | **1 日 5,000 通を超えたとき、または到達率の問題（迷惑メール判定・共有 IP のレピュテーション低下）が出たとき**に Amazon SES へ移行。Laravel のメーラーは `.env` の切替のみで移行でき、バウンス取り込みを SES の SNS 通知に差し替える |

## 12. 受け入れ基準（抜粋）

- WinDays で登録したユーザーが、同じメール/パスワードで `task.winroad.org` にログインでき、Free プランの上限（Team×1・招待1名）が適用されている
- 1日に 30 セグメントを帯入力しても、重複区間が作れず、日跨ぎのセグメントが両日の集計に正しく按分される
- 「今から仕事」→ 別カテゴリをタップしたとき、前のセグメントが自動終了し、新しい進行中セグメントが 1 つだけ存在する
- 習慣「毎月末営業日」が土日祝を避けて正しい日に発生し、達成チェックがストリークに反映される
- 1日サマリを保存すると WinTask の日記画面に同じ内容が表示される（`team_id = null`）
- Free ユーザーがダッシュボードで 5 週前を選ぶと、入力は妨げられずロック表示とアップグレード案内が出る
- 「明日もやる」で作成した個人タスクが WinTask の「自分の担当」に現れる
- 週次振り返りメールに配信停止リンクがあり、停止後は送信されない
- オプトインしていないユーザーに WinTask のお知らせメールが届かない
- 登録 API に 1 分間に 6 回アクセスすると 429 が返る

## 13. あえて入れないもの

| 機能 | 理由 |
| --- | --- |
| バックグラウンド GPS 追跡 | ストア審査・電池・プライバシーの三重苦。WinTask の位置記録要件定義書自身が警告。法人向け位置記録とは切り離す |
| SNS 的な公開・フォロー・共有 | 行動記録は機微情報。既定完全非公開とし、共有は WinTask の役割に限定することで設計とプライバシーポリシーを簡潔に保つ |
| 独自の日記テーブル | WinTask `diary_entries` で足りる。二重化するとデータ連続性という最大の武器を失う |
| 独自の課金・決済 | WinTask の Stripe をそのまま使う |
| ネイティブアプリ（初期） | 検索流入が主戦場で Web が必須。PWA で十分な体験を作ってから判断 |

## 14. 追加提案（標準仕様＋α）

1. **「空白を埋める」提案**: 前日の同時刻帯や習慣の目安時間帯から、未記録時間のカテゴリを提案してワンタップで埋める。継続率に効く
2. **今日の一言 AI 要約（将来）**: 1日サマリの自動下書きを Claude で自然文にする。無料は週次のみ、日次は有料など段階化
3. **バランス目標**: 「仕事は週 40h 以内」「運動は週 3 回」を目標として設定し、ダッシュボードで達成度を表示
4. **年間ヒートマップ**: 習慣達成・レジャー日を GitHub の草のように表示。SNS に貼りたくなる画像として書き出し（個人が能動的に共有する形なら機微情報の問題は本人判断）
5. **WinTask 側の「WinDays で記録」ボタン**: 逆方向の導線。WinTask の完了タスクからタイムログを 1 セグメント作る
6. **祝日カレンダーの共有**: WinTask の祝日データを習慣の休日判定に共用
