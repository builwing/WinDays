## 要件定義書を v0.3 に再構築（2026-09-11）

ユーザー要望「予定管理と行動管理を 1 つに。予定の開始時刻で自動的に記録を開始し、終了時刻で確認、3 分放置で予定どおり終了」を中核コンセプトにして要件定義書を再構築した。

- 中核: **予定駆動の自動記録**（§4.0・§4.4）。判定はサーバーの毎分スケジューラ `days:auto-track` と状態機械 `days_plan_runs`。通知やアプリの状態に依存しない
- 予定: WinTask の個人予定を共用（実装済み）＋ 繰り返し予定（`rrule` を 14 日先まで展開）＋ 初回設定ウィザード。習慣・ルーティンは繰り返し予定に統合（`days_habits`・`days_templates` 廃止）
- ネイティブ: **Flutter で別実装せず Capacitor で同じ React コードを配信**（§16）。Phase 4
- フェーズを組み直し: Phase 2 ＝ 自動記録（中核）、Phase 3 ＝ 習慣・サマリ・導線、Phase 4 ＝ ネイティブ・Google 連携
- 2026-09-11 に確定: 開始・終了とも猶予 3 分（放置後は予定時刻で確定）、習慣・ルーティンは繰り返し予定に統合、ネイティブは Capacitor、位置スタンプは Phase 4 候補に残す（無操作の GPS 自動取得は不採用・§16.1）
- 繰り返し予定の整合案を承認済み。WinTask `docs/予定・Googleカレンダー連携_要件定義書.md` v0.3 §15 に追記（`feature/windays-plans` にコミット）。実装は WinTask `feature/calendar-recurrence` → WinDays の順
